# 产品定义

> **AI 判断，Seal 验算，人拍板。**

## 一、要解决的问题

Seal 面向**所有需要传统 Office 格式交付的受控文档工作**——凡是必须按外部或机构规定的 Word 格式填写事实、撰写自拟章节、挂载证明材料、由有权人员拍板确认并导出终稿的高风险交付物（如招投标、专项申报、资质办理、尽调底稿、合规报告、竣工验收等），本质上都在解决同一类问题。

**当前阶段，我们以招投标作为首个端到端落地的具体场景，先把它推进到真实可用。** 在招投标闭环彻底打穿并经多份真实样本验证之前，不同时铺开其他场景的专属流程包；但底层文档引擎、知识库、身份范围、签名授权与定稿闸门必须按通用传统 Office 交付抽象，不为招投标特例污染通用底座。

以企业投标为例：必须按招标方规定的格式编写投标文件。这份格式通常藏在招标文件（Word）的某个章节里，章节名称和组织方式因招标方而异；要填写的内容散落在企业历年的证照、业绩、人员与方案资料中；报价、工期、质保、偏离等决定必须由有权人员拍板；任何一处格式被改坏、证照过期、主体用错，都可能导致废标。

Seal 让 DSH 中的 Agent 完成从“读源文件/招标文件”到“交出可审阅草稿”的全过程，并保证三件事：

1. 规定格式的原文没有被悄悄改动，改了的地方都看得见；
2. 写进去的机构/企业事实能追溯到知识库出处，证明材料在参考日（截标日）有效、持证主体没有用错；
3. 所有待拍板的决定与未核实的事实都以黄标留在 Word 里，直到人确认。

现实世界的 Office 源文件千奇百怪。Seal 不追求用穷举规则去拟合少数测试样本，而是从第一性原理抽离结构机制，并留出足够的保守冗余，让任何合法但杂乱的真实文档都能被稳健处理、透明验算。

## 二、一份投标文件由三种内容组成

| 内容 | 常见例子 | 怎么完成 |
| :--- | :--- | :--- |
| **格式文件** | 投标函、开标一览表、法定代表人身份证明、授权委托书、承诺函、偏离表、资格审查表、业绩表、人员表 | 从招标文件中原样取出；Agent 理解每个空并填写、加行、勾选；Seal 执行编辑、核对事实来源，并标出对原文的任何改动 |
| **自拟章节** | 技术方案、实施方案、售后服务、质量保证、培训方案 | Agent 按评分标准检索知识库素材并撰写；Seal 按文档原有样式把内容排进 Word |
| **证明材料** | 营业执照、资质证书、业绩合同、人员证书、审计报告等扫描件 | Agent 挑选材料；Seal 核验有效期与持证主体，并按版心排版图片 |

## 三、用户流程

1. **建库与维护**（一次建库、持续维护）：业务人员把历史标书、母本和证照扫描件交给 Seal；Agent 拆分、分类、摘取字段，生成“待核实”的资料记录；人在知识库中心核实关键字段。Seal 持续提示即将过期、效期未知、缺字段与未核实的资料。
2. **开启投标**：在 Seal 指挥台拖入招标文件，选择企业知识库并填写截标日，开启 AI 会话。Seal 自动建立项目目录，业务人员不需要填写任何路径。
3. **Agent 编写**：读招标文件、整理招标要求、取出格式文件、填写、撰写自拟章节、挂载证明材料，并反复自检直到检查报告中没有它能处理的问题。
4. **人审**：会话右侧的审阅栏按类别列出待拍板项、未核实事实、原文改动、内容丢失、未处理空白与招标要求缺口；人可以逐项确认、修改或交给 AI 改写，也可以下载草稿在 Word 中查看。
5. **定稿**：全部处理完成后导出终稿，Seal 清除自己加上的审阅标记，生成干净的 Word。

## 四、职责划分

| 角色 | 负责 |
| :--- | :--- |
| **AI** | 找格式章节、理解每个空的含义、读懂资格要求与评分标准、检索资料、撰写内容、决定排版、解释每处待定与改动 |
| **Seal** | 提供看文档、改文档、查资料的工具；当场拒绝会损坏文件或引用失效证据的操作；核对事实来源、有效期、持证主体与原文改动；生成检查报告；守住定稿闸门 |
| **人** | 核实知识库关键事实；拍板报价、工期、质保、偏离等决定；接受或否决对招标原文的改动；导出终稿 |

## 五、明确不做

- 不让 Agent 或脚本直接改写 Word XML；所有修改走 Seal 编辑原语。
- 不替人拍板商业决定，不让 Agent 确认待定项或把资料标为已核实。
- 不用代码替 Agent 做语义判断：不写正则规划器，不自动猜字段含义，不自动匹配资料。
- 不在生产代码中写死客户、项目、模板坐标或某个客户知识库的特有规则。
- 不让业务人员配置路径或工作区；项目目录与会话由 Seal 自动管理。
- 本阶段暂不铺开其他场景的专属流程包（但底层引擎与原语保持通用，面向传统 Office 受控交付，不写死招投标特例）；暂不支持只有扫描件 PDF 的招标文件的格式重建；暂不支持 Word 以外的交付格式；暂不做整包脱敏与元数据清洗。
