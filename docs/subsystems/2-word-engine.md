# 子系统 2：Word 引擎（`src/core/docx/`）

## 一、职责与边界

- 提供读取、复制、编辑、比较、校验与清理 Word 文档的确定性能力，经 DSH 工具 `seal_doc_read`、`seal_doc_extract`、`seal_doc_edit`、`seal_check` 供 Agent 使用（见[子系统 3](3-bid-workflow-and-checks.md)、[子系统 4](4-dsh-plugin-and-workbench.md)）。
- 不判断语义：不决定某个空该填什么、哪段是格式章节、哪些内容需要拍板。本模块不含招投标词汇；敏感关键词等领域规则在 `src/core/bid`。中文表单通用的留白语法（下划线、括号、年月日等）属于本模块的疑似空白提示。
- 只处理 `.docx`。`.doc` 由壳层经 `HostPort.convertDocToDocx` 转为项目目录中的副本后再处理。

## 二、地址

- 0 基计数，按文档顺序：
  - `p:N`：正文第 N 个顶层段落（只计顶层段落）；
  - `t:N`：正文第 N 个顶层表格；
  - `t:N/r:I`：表格第 I 行；`t:N/r:I/c:J`：该行第 J 个 `w:tc`（横向合并的格计一次；纵向合并的续格照常计数，视图标为续格）；
  - `t:N/r:I/c:J/p:K`：单元格内第 K 个段落；单元格内的嵌套表格继续追加 `/t:M/r:…/c:…`。
- 页眉、页脚、脚注、批注与文本框：视图中只读展示并注明“不可编辑”，编辑原语不支持；其中的疑似空白在检查报告中单独列出，由人处理。
- 地址指向文档的当前状态。同一批编辑中的所有操作都按该批开始前的状态寻址；编辑成功后，返回结果给出受影响区域的新地址。

## 三、文档视图（`readDocument`）

三种模式，输出都有长度上限；截断时明确说明，并给出继续读取的参数。

1. `outline`：标题树（依据段落大纲级别或标题样式），以及每节的地址范围、段落数、表格数与疑似空白数，用于定位格式章节与投标文件组成。
2. `blocks`：从指定地址起的连续块，默认上限 60 块。段落一行一条；表格按行列展开；疑似空白内联标注为 `⟦k:原文⟧`（k 为该块内序号）；复选项显示为 `□选项` 或 `☑选项`；图片与嵌入对象显示为 `[图片]`、`[对象]`；纵向合并续格显示为 `〃`；Seal 待定标记显示为 `«待定:类别»…«/待定»`；隐藏文字显示为 `‹隐藏›…‹/隐藏›`。
3. `search`：按字面文本检索，返回命中块的地址与前后少量文字，默认上限 30 条。

视图必须如实：除上述标注外，显示的文字与该块在 Word 中的可见文字逐字一致。

## 四、疑似空白提示（`detectBlankHints`）

- 识别规则（尽力而为）：两个及以上的连续下划线（`_`、`＿`）；带下划线格式的连续空格；空括号（`（ ）`、`( )`、`[ ]`、`【 】`）；括号内的填写提示（如“请填写……”，或以名称、金额、日期、编号等结尾）；日期留白（`年 月 日` 前缺数字）；`XX`、`××` 占位；非合并续格的空单元格；复选组；挂载提示（如 `【提供……复印件】`、“（格式自拟）”）。
- **提示没有跨版本身份**：每次都从当前文档重新计算，不登记、不跟踪迁移。同一版本内以 `<地址>#k` 引用（k 为该块内序号），只在该版本内有效。同一文档多次计算结果必须相同。Agent 或人对提示的“跳过”由子系统 3 按块文字指纹记录。
- **提示不是写权限**：编辑原语可以修改任何可编辑位置。提示只用于视图标注和检查项 C02、C03。
- **提示只能加严**：提示只会增加待处理项，不会让任何改动免于检查；差异比较（第七节）不得使用提示。漏报不是缺陷，误报的代价是 Agent 写一句跳过理由。

## 五、编辑原语（`applyEdits`）

### 5.1 批次语义

- 一次调用提交一批操作。全部有效才写入；任何一个被拒，整批不生效，草稿保持原样，并返回每个操作的结果与可执行的修改建议。
- 每次写入后执行文件合法性校验（第八节）。校验失败视为引擎缺陷：拒绝写入、保留上一版草稿并报告。
- 文本值中的事实引用（`{{…}}`）由 `src/core/bid` 在调用本模块前解析为纯文本（见子系统 3 第二节）；本模块只接收解析后的文本与待定要求。

### 5.2 定位

- 改动文字的操作必须给出 `at`（地址），以及 `find`（该块可见文字中恰好出现一次的原文片段）或 `blank`（视图中该块的提示序号）二者之一。片段不存在或出现多次即拒绝，并在建议中列出候选。
- 被替换的文字可能跨多个 run；引擎按可见文字定位，并保持片段以外的 run 不变。

### 5.3 操作清单

| 操作 | 作用 | 关键规则 |
| :--- | :--- | :--- |
| `replace` | 把块内一段原文替换为新文字 | 首尾未改变的文字片段及多空位间的固定文字分隔符（如“年/月/日”）保留各自所在 run 的原有格式；新填入或改写的片段从对应空位自身 run 继承格式（单空位跨混合 run 时优先取带下划线的空位 run，但不给无下划线区凭空加线）；值中的换行写为同段软换行 |
| `set_cell` | 给没有可见文字的单元格写入文字 | 保留单元格内的图片、对象与段落属性；若首段含非文字内容则另起一段；格式取同行或同列最近的有文字单元格；单元格已有文字时拒绝 |
| `insert_rows` | 以某一行为模板插入若干行 | 深拷贝模板行的边框、宽度与样式；`mode: after` 在模板行后追加，`mode: replace` 用新行替换模板行（如示例行） |
| `delete` | 删除段落、表格或表格行 | 用于删除填表示例、说明等；结果在差异报告中列为删除原文；按整批终态禁止因删除段落而令相邻表格失去分隔段并合（同批删表或插入分隔段时允许）；默认禁止误删承载分节符（`w:pPr/w:sectPr`）的段落，合法整节删除须显式指定 `allowDeleteSectionBreak: true` |
| `insert` | 在某块之前或之后插入 Markdown 内容 | 支持标题（映射到文档已有的各级标题样式；缺失对应标题样式时使用加粗段落并写入显式 `<w:outlineLvl>` 以接入 Word 导航与 `insert_toc`，同时仍向调用方报告缺失）、段落、有序与无序列表、表格、粗体、斜体、分页符与图片；正文样式取锚点段落或文档默认样式；表格按第十一节写入明确的几何信息与排版属性 |
| `check` | 设置某个复选项 | 按选项文字定位；只改变选项前的符号（`□`/`☐` 与 `☑`/`■`/`√` 互换），不改动其他文字 |
| `insert_image` | 在某块之后或空单元格中插入图片 | 图片必须可解码；按第十一节计算插入点的可用宽高并等比缩放（只缩不放），不超出所在单元格与页面；登记关系与内容类型 |
| `mark_pending` | 把已有文字标为待定 | 用 `_Seal_P_` 范围包住目标片段并加黄色高亮，由子系统 3 登记类别与说明 |
| `insert_toc` | 在顶层块之前或之后插入 Word/WPS 原生目录域 | 收集正文 1..`maxLevel`（默认 3）级标题（按大纲级别与标题样式），排除锚点自身“目录/Contents”标题（并将其 `<w:outlineLvl>` 设为 `9` 防止更新域自引用）；为目标标题补齐不冲突的 `_TocSeal_*` 书签，写入标准 `TOC \o "1-<maxLevel>" \h \z \u` 域与右对齐点线引导符缓存条目（内含 `PAGEREF _TocSeal_* \h` 与可选宿主渲染真实页码），并在 `word/settings.xml` 写入 `<w:updateFields w:val="true"/>`；若锚点紧邻已有目录域则幂等替换刷新；不触发自动标黄 |

- `replace`、`set_cell`、`insert_rows`、`insert` 也可以携带 `pending: { category, note }`，写入的文字直接带黄标并登记为待定项。
- 子系统 3 可以要求把某个操作写入的文字包进一个 Seal 范围（第九节），引擎负责落位并分配不重复的书签编号。
- 编辑与已有 Seal 范围的关系：
  - 编辑区间落在某个范围之内（含与范围完全重合）：范围保留、编号不变，范围内文字随之改变；
  - 编辑区间完整覆盖并超出某个范围：该范围随被替换的文字一起移除；
  - 编辑区间与某个范围部分交叉（只覆盖一端）：拒绝整批，提示 Agent 整体替换该范围或只改范围内部；
  - Seal 范围之间不交叉、不嵌套；`mark_pending` 的目标与已有范围部分交叉时同样拒绝。
- 当场拒绝的情形：地址不存在；定位片段不唯一或不存在；目标位于不可编辑区域；值含 XML 禁止的控制字符或无效 Unicode（不得静默删除字符）；图片无法解码；`set_cell` 的目标已有文字；编辑区间与 Seal 范围部分交叉；子系统 1、3 规定的资料与证据拒绝条件。

### 5.4 返回

每个操作的状态；受影响块编辑后的视图（含新地址）；本批新增的待定项与关键词加严结果。

## 六、区间复制（`extractRanges`）

- 输入：源文档；一个或多个按顺序给出的顶层块范围（如 `p:120..t:15`）；分册名称。
- 输出：`draft/<分册>.base.docx`（基准稿，此后不再修改）与 `draft/<分册>.docx`（工作稿，初始与基准稿相同）。
- 保留样式、编号、主题、字体表与设置；保留被复制块引用的图片、页眉页脚与关系。分节属性取最后一个被复制分节的属性，没有则取源文档末尾的分节属性。
- 成对标记（书签、批注范围、权限范围、修订移动范围、自定义 XML 范围）被范围边界切断时，在复制件中删除该对标记残留的一端，并在结果中逐项报告；不得留下孤立的起止标记。
- 源文档中名称以 `_Seal_` 开头的书签在复制件中改名并报告，避免与 Seal 范围混淆。
- 源文档不做任何修改。

## 七、差异比较（`compareDocuments`）

- 输入只有基准稿与草稿两份文件，不读取台账、编辑记录或疑似空白提示；名称以 `_Seal_` 开头的书签是 Seal 自己的标记，比较时忽略。
- 先按块的文字与结构对齐基准稿与草稿（插入与删除不影响其余块的对齐），再逐项分类：

| 类别 | 含义 | 对应检查 |
| :--- | :--- | :--- |
| `filled` | 基准稿中被替换的部分只由**空位字符**组成（见下），或原本是空单元格、空段落 | 正常，列入填写清单 |
| `inserted` | 新增的块或表格行 | 正常，列入新增清单 |
| `modified` | 基准稿中被替换的部分含有空位字符以外的文字 | C06 原文改动 |
| `deleted` | 基准稿中的块或表格行被删除 | C06 原文改动 |
| `objectLost` | 基准稿中的图片、嵌入对象、域或书签在草稿中不复存在 | C07 内容丢失 |
| `formatChanged` | 段落/表格/行/单元格结构属性改变（不因文字填写或改写而免检），或文字未变而 run 属性改变 | C06（提示级） |

- **空位字符**只包括：空白（含全角空格）、下划线（`_`、`＿`）、内部只有空白的括号对（`（ ）`、`( )`、`[ ]`、`【 】`）、日期中“年”“月”“日”之前缺数字的位置（被替换为数字，年月日字样保留），以及复选符号在 `□`/`☐` 与 `☑`/`■`/`√` 之间的切换。判定只看字符类别，不看词语含义。
- `modified` 中被替换的原文恰好是一个完整括号段，或完全位于一对括号之内时，标注子类 `bracketText`（如“（投标人名称）”或“（合同金额）”被改写）。子类只用于审阅时分组与批量处理，仍属 C06。
- 每项差异有稳定编号，由基准地址、改前文字与改后文字计算；人工接受以该编号记录。同一位置的内容再次变化会产生新编号，旧的接受随之失效。

## 八、文件合法性（`validatePackage`）

- 所有 XML 部件都能被标准 XML 解析器（`saxes`）解析，且不含 XML 禁止的字符；
- 所有关系目标存在，所有部件与媒体在 `[Content_Types].xml` 中登记；
- 所有图片可解码；ZIP 结构可被常规解压工具读取；
- 每次写入草稿、复制区间与导出终稿都必须通过本校验。

## 九、Seal 范围、待定标记与定稿清理

- **Seal 范围**是 Seal 写在文档里的隐藏书签：`_Seal_P_<编号>` 包住待定内容，`_Seal_F_<编号>` 包住经事实引用写入的内容。身份随文字一起移动，台账只按编号记录类别、来源与确认（子系统 3），不按地址或偏移量追踪；编辑与范围的关系见第五节。
- **待定标记**是 `_Seal_P_` 范围内文字所在 run 上的 `<w:highlight w:val="yellow"/>`。
- **可见性检查**（`auditPendingMarks`）独立解析草稿：台账中每个未确认的待定项，其范围必须存在，且范围内所有非空白文字都带黄色高亮，否则报告 C10。
- **定稿清理**（`finalizeDocument`）移除全部 Seal 范围，并只移除已由人确认的 `_Seal_P_` 范围内的 Seal 高亮；招标文件原有的高亮、书签、批注等不受影响。清理结果必须通过文件合法性校验，且与清理前的草稿相比只有高亮与 Seal 书签的变化。

## 十、渲染与性能

- 页面渲染经 `HostPort.renderDocxPages`（LibreOffice），必须使用含中文字形的字体配置；工作台预览与测试使用它，Agent 自查也可以使用宿主自带的 Office 渲染工具。
- 引擎必须能在宿主默认内存上限内处理真实规模的文件：两份真实母本（约 84 MB 与 105 MB）的入库，以及真实招标文件的视图与复制。必要时按部件流式处理，避免同时持有全部图片字节与全文字符串的多份副本。

## 十一、表格与页面几何（`layoutBox`）

插入点的可用宽高只由一个确定函数计算，所有插图路径（`insert_image`、`insert` 中的 Markdown 图片、标注包装）与 C16 审计都调用它，不得另设列数提示等旁路。因纯 XML 无法完整复刻所有 Office 引擎的排版流，几何模型遵循**第一性原理与保守冗余**：主动控制 Seal 生成的结构，对无法静态判定的外部约束采用安全下界，遇几何无解容器透明保留草稿并由 C16 报出。

- **正文与多栏**：可用宽度为所在分节的版心宽度（页宽减左右页边距与装订线）；分节有多栏（`w:cols`）时，等宽栏取单栏宽度；**不等宽栏采用保守安全下界——取该节所有栏宽的最小值**，保证图片无论自然流落到哪一栏都不越界。可用高度为版心高度。
- **单元格与行高**：
  - 水平：取所在表格 `w:tblGrid` 中该格覆盖各列（计入 `w:gridBefore` 与 `w:gridSpan`）的宽度之和；表格声明了 `dxa` 或 `pct` 表宽且与网格总宽不一致时按比例换算；再减去左右单元格边距，依次取 `w:tcMar`、`w:tblCellMar`、表格样式（含 `basedOn` 继承）、文档默认表格样式；`w:tcW` 只能进一步收窄，不能放宽；结果逐层不超过外层位置（上一级单元格或版心）的可用宽度，嵌套表逐层计算。
  - 垂直：逐层扣除所有祖先单元格的上下边距（`top` / `bottom`）；若任意祖先表行声明了**精确行高**（`w:trHeight w:hRule="exact"`），按精确行高扣除上下边距、格内既有段落/嵌套表/非 Seal 图片以及标注与基线占位后，由同格内待放置的 Seal 图片均分剩余高度。无可用正空间时可用宽高记为 `0`（不虚构正容量），草稿仍可输出并由 C16 阻断定稿。
- **段落缩进、同行占位与精确行距**：计入所在段落经文档默认样式与样式继承后的有效左右缩进与首行/悬挂缩进（同时支持 twips 与字符单位 `Chars`），以及插图前的同行文字占位宽度；段落声明精确行距（`w:spacing w:lineRule="exact"`）时同时约束可用高度。
- **缺少几何信息**：表格缺少 `w:tblGrid` 或网格宽度为零时，按该行的列数（计入 `gridBefore`/`gridAfter`/`gridSpan`）平分外层可用宽度，再减去边距。表格内任何情况下都不退回整页宽度。
- **高度余量与分页**：版心高度扣除标注行数与显式安全余量；图片与其可见标注（含第三方持证方标注及普通待核对图片标注）作为不可拆分的整体排在同一页。
- **Seal 生成的表格与图片段落**：
  - Markdown `insert` 生成的表格与标注包装一律写明确几何：`w:tblW`（dxa，等于插入点可用宽度）、`w:tblLayout w:type="fixed"`、带宽度的 `w:tblGrid`（默认等宽分列）与每格 `w:tcW`（dxa）；Markdown 自生成表格按 `wml.xsd` 顺序同时写入细边框（`w:tblBorders`）、单元格内边距（`w:tblCellMar`）、跨页重复表头（`w:tblHeader`）与防跨页断行（`w:cantSplit`）；嵌套表位于单元格末尾时补足合法尾段落，避免吞并相邻格或后续正文。
  - Seal 生成的图片段落采用**中性段落属性**（显式清零 twips 与字符单位缩进、单倍自动行距、不从脏模板继承缩进或固定行距）；图片在整批编辑确立最终容器结构后统一按 `layoutBox` 等比缩放（只缩不放）。
- 几何模型本身的正确性用覆盖机制输入维度域的矩阵测试与渲染矩阵（容器、行高、分栏、缩进、边距、图片形状、插入路径、有无标注）人工看图验证，不能只用同一个模型自证。
