# 子系统 1：企业知识库（`src/core/kb/`）

## 一、职责

- 面向受控传统 Office 文档交付的机构/企业资料柜（当前以企业投标资料为首个落地形态）：存储、校验与检索主体档案、证据记录和写作素材；把母本与扫描件转为入库候选；按参考日期（投标场景为截标日）体检有效期与持证主体。
- 存储形式是 Agent 能直接读取和检索的文件；所有写入都经 `src/core/kb` 的函数执行，保证格式与校验一致。底层存储、签名与校验机制保持通用，不依赖特定客户或模板结构。

## 二、存储结构

```text
~/.seal/vaults/<vaultId>/        （SEAL_HOME 覆盖 ~/.seal）
  vault.json         格式标识 seal-kb-2、vaultId、显示名称、创建时间
  subject.md         主体档案
  records/<id>.md    证据记录（一份证照、一份业绩合同、一张人员证书……）
  materials/<id>.md  写作素材（公司简介、方案段落、案例描述……）
  files/             原件与图片（扫描件、母本拆出的图片），以相对路径引用
  inbox/<批次>/       入库候选（母本拆分结果），处理后标记为已处理
  log.jsonl          变更日志：时间、操作者（agent 或 human）、对象、变化摘要
```

- 每个 `.md` 文件由一段扁平的 frontmatter（字符串、日期、字符串列表）与 Markdown 正文组成。未知字段原样保留，并在体检中提示。
- `id` 由系统生成，只含字母、数字、连字符与中文，不含路径分隔符，在同一知识库内唯一。
- 旧格式 `seal-vault-1` 与旧 Markdown 知识库编译器（`00_投标主体.md`、`00_编标行为规则.md` 等）不再支持，也不提供迁移。

## 三、主体档案（`subject.md`）

| 字段 | 含义 |
| :--- | :--- |
| `legalName` | 法定名称 |
| `creditCode` | 统一社会信用代码，必须通过 GB 32100 的格式与校验位检查 |
| `legalRepresentative`、`registeredCapital`、`establishedOn`、`address`、`phone`、`email`、`bankName`、`bankAccount` | 常用登记信息 |
| `forbiddenAffiliates` | 严禁混用的关联企业名称列表 |
| `thirdPartyHolders` | 允许作为配套资料持证方的第三方（如部件厂家）名称列表 |
| `verifiedFields` | 已由人核实的字段名列表 |

正文可写公司概况等自由文字。

## 四、证据记录（`records/<id>.md`）

| 字段 | 含义 |
| :--- | :--- |
| `type` | 营业执照、资质证书、认证证书、许可证、人员证书、社保证明、业绩合同、验收证明、财务审计、纳税证明、信用证明、授权文件、其他 |
| `title`、`number`、`issuedOn` | 名称、编号、发证日期 |
| `holder` | 持证或签约主体；人员类资料填人员姓名，另填 `employer`（所属单位） |
| `validUntil` | `YYYY-MM-DD`、`长期` 或 `不适用`；**缺省表示效期未知**，不得被当作不适用 |
| `client`、`projectName`、`amount`、`signedOn` | 业绩类资料的甲方、项目、金额与签订日期 |
| `files` | 原件与图片的相对路径列表 |
| `source` | 出处（母本文件名与章节、扫描件文件名等） |
| `tags` | 自由标签 |
| `verified`、`verifiedAt` | 是否已由人核实及核实时间 |

- `不适用` 只能来自资料原文的明确表述或人的设置，不得根据标题猜测。
- 证据记录是原子的：一份资料一条记录，不存在“容器记录”。需要成组使用的资料，投标时由 Agent 分别引用。

## 五、写作素材（`materials/<id>.md`）

- frontmatter 包括 `title`、`tags`、`source`；正文为 Markdown，可以引用 `files/` 中的图片。
- 素材供 Agent 检索与改写。Seal 不核验其内容，只在投标时记录引用来源。

## 六、体检（按参考日期，通常为项目截标日）

| 体检项 | 规则 |
| :--- | :--- |
| 有效期 | 早于参考日为“已过期”；参考日起 60 天内为“即将过期”；`长期` 为有效；缺省为“效期未知”（亦须提示）；非法日历日期报错。所有日期必须是合法的日历日期 |
| 持证主体 | 企业类资料：`holder` 等于 `legalName` 为本企业；属于 `forbiddenAffiliates` 为“禁用主体”；属于 `thirdPartyHolders` 为“第三方”；缺省为“主体未知”；其他名称为“主体不符”。人员类资料按 `employer` 判断 |
| 原件 | `files` 中的文件存在、非空；所有入库与挂载支持的图片格式（PNG/JPEG/GIF/BMP/TIFF/SVG/WMF/EMF 等）均须可解码 |
| 关键字段 | 证照类缺 `holder`、`number` 或 `validUntil`，业绩类缺 `client`、`amount` 或 `signedOn`，均逐字段列为缺项 |
| 未知字段 | frontmatter 中出现未定义字段时原样保留，并在体检中提示 |
| 核实状态与签名 | 未核实的记录、主体中**每一个未核实的非空字段**（不得因部分字段已核实而掩盖其余未核实字段），以及**核实 HMAC 签名无效或内容已被外部篡改的记录与主体字段**，均须进入 `health()` 报告 |
| 重复 | 同类型、同编号的记录（跨记录聚合报告） |

## 七、多格式材料入库（`ingest`）

- 面向真实世界杂乱的机构/企业资料目录，统一支持多容器确定性拆分为 `inbox/<批次>/` 入库候选与 `files/<批次>/` 资产，**原件 100% 只读、不做语义猜测、重复入库不覆盖、失败只回滚本批次新增内容**：
  1. **Word 文档（`.docx` / `.doc`）**：`.doc` 先经宿主 LibreOffice 转换为 `.docx`；按大纲级别确定性拆分为候选，正文与表格转为 Markdown，内嵌图片一张不丢写入 `files/<批次>/`，保留从标题剥离的复用标记文字（如“直接套用”“标黄”，仅作提示）与原文位置；能在宿主默认内存上限内完成两份真实母本入库。
  2. **PDF 文档（`.pdf`，含电子版与纯扫描件）**：经宿主提取逐页文字层并按安全上限（如每份 PDF 至多渲染 120 页，超出页数透明标注 `truncatedPages` 而不静默丢失）逐页光栅化为可挂载进 Word 的高清 PNG（150 DPI，逐张校验可解码），保留原 PDF 存档于 `files/<批次>/`；按合理页窗（如每 10 页或单份 <= 10 页合并为 1 条）生成 `inbox/<批次>/` 候选，无文字层页面显式注明疑似扫描件并列出对应 PNG 路径，供 Agent 看图摘取字段并在编标时直接把该页 PNG 挂载进 Word。
  3. **散装图片（`.png` / `.jpg` / `.jpeg` / `.gif` / `.bmp` / `.tif` / `.tiff` / `.svg` / `.wmf` / `.emf` / `.webp`）**：逐张真实验码校验（损坏或伪造字节当场报错回滚）；`.webp` 转为 Word 原生兼容的 `.png` 存入 `files/<批次>/`；每张生成 1 条视觉候选供 Agent 看图分类建档。
  4. **电子表格与纯文本（`.xlsx` / `.xls` / `.ods` / `.csv` / `.tsv` / `.txt` / `.md`）**：`.xls`/`.ods` 先经宿主转 `.xlsx`；核心层以纯 XML/ZIP 解析 `.xlsx` 与 RFC-4180 解析 `.csv`/`.tsv`，按工作表/合理行窗转为 Markdown 表格候选；`.txt`/`.md` 严格 UTF-8 解码后生成文本候选。
  5. **目录递归与透明跳过**：支持直接传入文件列表或本地目录路径（目录递归枚举常规文件、跳过隐藏点文件并执行 `assertOutputIsolation` 防自递归）；显式传入单个不支持文件直接报错，目录中夹杂的少量无关不支持文件透明记入 `skipped` 列表（目录内若零有效材料则明确报错）。
- 入库只做确定性拆包；由 Agent（配合内置 `seal-kb` 操作手册，支持在知识库中心一键拉起「让 AI 分类整理」会话，刷新页面后仍可续推未处理批次）阅读文字与查看扫描件 PNG，决定归入主体档案、证据记录或写作素材并通过 `seal_kb_save` 写入，写入结果均为未核实，最终由人在知识库中心核实。

## 八、检索（`searchKnowledge`）

按关键词检索标题、正文、字段与标签（中文按单字或二元组匹配），可按类型、标签与有效期状态过滤。返回有上限的简要结果：`id`、类型、标题、关键字段、有效期状态与命中片段。

## 九、写入权限

- Agent 可以新建、修改、删除记录与素材，可以附加文件，但不能设置 `verified`、`verifiedAt`、`verifiedFields` 或内部 `__seal*` 字段；携带这些字段的**任何**写入动作（包括 `create`、`update`、`delete`、`attach_file`、`dismiss_candidate`）在执行前一律直接拒绝，不得改动文件或日志。
- 核实只能由人在工作台完成。已核实的记录或字段发生实质内容变化后，核实状态自动清除；对记录执行未产生字段或正文变化的保存时，不得静默破坏已有的有效核实签名。
- 核实标记带有用 `SEAL_HOME/keys/` 中的密钥对记录内容指纹计算的 HMAC；直接改写文件伪造或被外部篡改的核实标记签名无效，一律视为未核实，并在体检（`health()` 与单条读取）中明确报告。
- 每次写入都追加变更日志。
- **工作台人工删除与资产回收（仅 owner 界面开放）**：
  - **删除单条记录/素材**：仅限 `record` 与 `material`（不得删除 `subject`），须先校验当前内容 `revision` 防并发误删，删除 `.md` 文件并追加 `actor: "human"` 变更日志（不误删共享原图目录；若已有草稿引用该记录，C05 将确定性报出来源缺失）。
  - **删除导入批次**：校验 `batchId` 格式（`^batch-[a-z0-9-]+$`）与 `inbox/<batchId>/` 存在后，先扫描全库活跃条目（`subject.md`、`records/*.md`、`materials/*.md`）收集 `files` 与正文中全部已引用的库内相对路径（含 URL 编码形式），删除 `inbox/<batchId>/`，并**仅清理 `files/<batchId>/` 中未被任何已建档条目引用的副本文件**（若存在无法解析的损坏条目则保守保留该批次 `files/<batchId>/` 资产防误删），追加 `actor: "human"` 变更日志。
  - **删除整个知识库**：须经宿主路径隔离校验（确认目标为 `vaultsRoot` 直接普通子目录、非符号链接），并确认当前无任何投标项目引用该 `vaultId`（若有项目引用或存在无法读取的损坏项目则 fail-closed 拒绝并给出清晰原因）；仅删除 `~/.seal/vaults/<vaultId>/`，绝不触碰用户本地原件。
